A recipe was already the thing a fragment carried, and the reason given was that a recipe can be replayed on an older tag. Until now nothing replayed it.

`node tools/notes-shots.mjs --before v0.20.0` builds a worktree of that tag, raises the office it had — old server, old floor — and walks it through the same recipe. The frame lands next to the new one, carrying the tag in its name, and the note prints the pair: *Before, v0.20.0* above the old picture, *After* above the new one. Without a tag the flag replays on the last release.

The tag lives in the file name rather than in a sidecar on purpose. A picture that has lost track of which version it shows is asserting something about no version in particular, and a sidecar is exactly the file that gets left behind in a move.

The pair below is the mechanism vouching for itself. Nothing about this feature is visible on a floor, so the two frames differ in everything else instead: the office of `v0.12.0` spoke Russian by default, drew itself at ×2 on a smaller canvas, and called the standup an обход. That is the old server answering, not a caption.

What no check can do is tell whether the old office understood the recipe. A room this feature added does not exist back there, a key does nothing, and the walk ends somewhere else entirely — the frame comes back plausible and wrong. The run says so at the end, and a before frame is looked at before it is committed.
